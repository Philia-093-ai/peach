# preflight-check · 发布前检查

> 一句话：**登机前的检查单**——飞机能飞，不代表可以飞；起飞前必须逐项打钩。
> 这份清单只干一件事：把「上线前必须成立的事」固定下来，跑一遍，红了就别发。

## 为什么需要它

发布出错的代价**不对称**：

- 代码 bug → 用户骂一句，改了再发，问题不大；
- **密钥泄露 → 钥匙永久外泄**，删代码也赎不回来（历史里翻得到）；
- 线上坏了没人发现 → 用户默默走掉，你连骂声都听不到。

所以「发布前」这个动作不能靠记性，只能靠清单。

## 什么时候用它

- 每次 `tcb hosting deploy` / 云函数部署**之前**
- 改动 `public/` 或 `cloudfunctions/` 之后
- 有人说「准备上线」「发版前检查」「preflight」

## 怎么跑

```bash
# 全量（含公网检查）—— 在仓库根目录执行
python .workbuddy/skills/preflight-check/check.py --repo .

# 网络/代理不通时跳过公网项（P1 全部标 SKIP）
python .workbuddy/skills/preflight-check/check.py --repo . --offline
```

脚本输出一张分组表：每项 ✅ / ❌ / SKIP + **证据**（文件名:行号 / HTTP 状态）。

- **任何 P0 项 ❌ → 结论就是「不许发布」**，先修再跑，别抱侥幸。
- 脚本只是把手动检查固定成一条命令，**它不是 CI**：不监听、不自动触发、不卡合并，需要人手动跑。

## 检查项（15 项，5 组）

### P0 上线红线（一条不过就不许发）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 1 | 全仓库无密钥特征词 | `ghp_` / `github_pat_` / `AKID` / `sk-` / `-----BEGIN … PRIVATE KEY` / 超长 `Bearer` 令牌 —— 0 命中 |
| 2 | `.env` 里的真实值没漏进代码 | 读 `.env` 每个值，对全仓库反查 —— 0 命中 |
| 3 | `.env` 不在仓库里 | 未被 `git ls-files` 跟踪 **且** 被 `.gitignore` 命中 **且** `git log --all -- .env` 为空 |

### P1 线上可用性（公网）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 4 | `/api/health` 通 | 200 且 `ok:true`，`service` 正确 |
| 5 | 接口版本一致 | `/health` 返回的 version == `cloudfunctions/api/package.json` 的 version |
| 6 | 读接口通 | `/api/scenes`、`/api/library` 200 且形状符合 `docs/api-contract.md` |
| 7 | 静态托管与仓库一致 | `public/` 每个文件的 md5 与线上逐个相同（防止「改了没部署」） |
| 8 | 首页可访问 | 公网首页 200 且含站点标题 |

### P2 错误说人话（Day 23 沉淀）

| # | 检查项 | 判据 |
| --- | --- | --- |
| 9 | 错误响应无堆栈、无裸状态码 | 错误体只有 `{ok:false, error:"中文", type:"…"}`，不含 `at ` 堆栈行 |
| 10 | 前端无裸报错 | 源码里搜不到 `'HTTP ' + res.status` 这类直接把状态码抛给用户的写法 |

### P3 代码硬规则

| # | 检查项 | 判据 |
| --- | --- | --- |
| 11 | 结果区无 `innerHTML` 注入 | `public/*.js` 渲染用户内容一律 `textContent`（`innerHTML = ''` 清空不算违规） |
| 12 | 无静默吞错 | 搜不到**裸的**空吞（`except: pass` / `catch (e) {}`）——真要吞，括号里必须写一句注释说明为什么 |
| 13 | 异步条件请求有竞态守卫（Day 24） | `library.js` 含请求序号 + 待跑补跑；`live.js` 含序号守卫 |

### P4 仓库卫生

| # | 检查项 | 判据 |
| --- | --- | --- |
| 14 | 没把大文件/临时文件带进来 | 待提交清单里没有 > 1MB 的文件、没有 `_` 前缀或 `tmp` 目录 |
| 15 | 待提交文件已分类 | 工作区没有「好几天的活堆一起」的迹象（未跟踪文件需点名说明归属） |

## 红了怎么办

| 项 | 常见原因 | 怎么修 |
| --- | --- | --- |
| 1 / 2 | 调试时把密钥贴进了代码 | 删掉该行，改成读环境变量（`process.env.XXX`） |
| 3 | `.gitignore` 漏了 `.env` | 补一行；**若历史上提交过，删文件不够，必须换密钥** |
| 5 | 忘了同步版本号 | `index.js` 的 VERSION 与 `package.json` 一起改 |
| 7 | 改了前端忘了部署 | 重新 `tcb hosting deploy public` |
| 11 | 用 `innerHTML` 拼卡片 | 改 `textContent`（Day 7 的 A10 老规矩） |
| 13 | 忙锁 `if (busy) return` 静默丢单 | 改「不丢单 + 最后一次赢」（Day 24 配方） |

## 留痕（每次跑完都要写）

追加到 `docs/day25-preflight-log.md`：

```
## 发布前检查 · YYYY-MM-DD HH:MM · 目的
- P0 3/3 ✅  P1 5/5 ✅  P2 2/2 ✅  P3 3/3 ✅  P4 2/2 ✅
- 结论：可以发布 / 不许发布（红了哪项：…）
```

## 常见坑（踩过就记下来）

- 只查「代码里有没有 key」**不够**——必须拿 `.env` 的真实值反查：密钥可能被改名、拆开写、塞进别的文件。
- `git ls-files .env` 有输出**不等于**一定泄露（可能只是历史上加过又被忽略）；三条判据要一起看。
- 公网检查会因为**代理/网络**失败，那不是代码问题 → 加 `--offline` 跳过并记一笔，别误判成「线上坏了」。
- 检查脚本自己也会骗人：一句 `except: pass` 会让「0 命中」变成**假阴性**（Day 24 在探针上踩过这个坑）。
- **检查器会两头骗人**：除了假阴性，还会**假阳性**。Day 25 首跑就抓到两处：
  ① 把注释里写的反面教材（`// 以前这里是 throw new Error('HTTP ' + res.status)`）当成真代码；
  ② 把 `.env` 里的**公开环境 ID**（`TCB_ENV`）当成泄露。所以规则是：
  **扫代码先剥注释**、**公开标识走白名单**、**报错必须给「文件:行号 + 命中哪条规则」**——
  没有这三样，红了也不知道是真红还是误报，清单就没人信了。
- **检查只扫「被跟踪文件」（Day 26 发现的洞）**：新写的文档/代码在 `git add` 之前是**未跟踪**状态，
  会被整份跳过 —— 于是「今天刚写的东西」恰恰是**唯一没被查的**。
  所以发布日必须**在 add/commit 之后再跑一遍**，顺序是「先提交 → 再检查 → 再部署」。
  实例：Day 25 那份验证记录（写进了一个假的完整令牌当"证据"）当天没被查到，因为当时它还 untracked；
  Day 26 发布时它已被跟踪，P0 第 1 项当场红。
- **证据文档里的假密钥也要打码**：把 `ghp_xxx…` 全文写进文档，等于**用"证明自己查过密钥"的方式把仓库搞脏**。
  正确写法：留前缀 + 字符数（`ghp_<已打码·共40字符>`），形状和长度都在，完整串不落库。
- 本机 GitHub 走 WattToolkit 代理，代理抽风时 P0 的 git 类检查不受影响（纯本地），但 **push 会失败**——检查清单管的是「能不能发」，推不上去是另一回事。
