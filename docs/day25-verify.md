## 0. Skill 在哪、怎么用

- **真身（入库）**：`.workbuddy/skills/preflight-check/SKILL.md` + `check.py`（检查清单与脚本放在一起，自包含）

- **README 用法**（余力加练）：`README.md` 新增「发布前怎么检查」一节

```bash
python .workbuddy/skills/preflight-check/check.py --repo .            # 全量（含公网）
```

## 2. ② 制作检查 Skill

- `check.py`（约 480 行，纯标准库）：跑 git 扫描、公网探测、源码规则检查，输出分组表 + 证据 + 结论，**P0 红 → 退出码 1**。

## 3. ③ 实跑验证（核心：先修误报，再故意弄坏）

### 第一轮：首跑就抓出 3 处（2 处是检查器自己的误报）

| 项 | 定性 | 处理 |
| --- | --- | --- |
| P0-2 `.env 真实值` 报 TCB_ENV 泄露 | **误报**：`TCB_ENV` 是公开环境 ID，本来就该出现在配置里 | 加 `PUBLIC_ENV_KEYS` 白名单 |
| P2-10 裸报错报 `mock.js:25` | **误报**：那是 Day 23 注释里写的反面教材 | 扫代码先剥注释（`strip_js_comment`，避开字符串里的 `https://`） |
| P3-12 空 catch `app.js:105` | **真问题**：降级复制里故意吞错却没说明 | 按新规则补注释（"要吞必须写明为什么"） |
| P1-7 托管不一致 | **真问题**：改了 `app.js` 没部署（11707B vs 11837B） | 重新 `tcb hosting deploy public` 后 md5 全一致 |

> 这一步的价值：**检查器也会两头骗人**。不修掉假阳性，绿灯没人敢信；不抓假阴性，红灯形同虚设。

### 第二轮：基线（可以发布）

15 项：P0 3/3 ✅ · P1 5/5 ✅ · P2 2/2 ✅ · P3 3/3 ✅ · P4 1/2 ⚠️（6 个老日子遗留的未跟踪文件，Day 24 报告过同一批）→ **结论：可以发布**，退出码 0。报告原文 `_d25_preflight_baseline.txt`。

### 第三轮：故意弄坏（必交证据）

往 `cloudfunctions/api/index.js` 顶部常量区塞了一行假密钥：

```js
const LEGACY_DB_TOKEN = 'ghp_<已打码·共40字符>';
```

同一份清单、同一条命令，结果：

- P0-1 **❌**：`发现 2 处：cloudfunctions/api/index.js:74 命中「GitHub 个人令牌」；命中「硬编码密钥赋值」`
- 结论翻转成 **「❌ 不许发布」**，退出码 **1**
- 报告原文 `_d25_preflight_caught.txt`；截图 `docs/day25-preflight-caught.png`

### 第四轮：撤销后复跑（闭环）

删掉那一行再跑：P0 恢复 3/3 ✅、结论「可以发布」、退出码 0（`_d25_preflight_restore.txt`）。

**闭环成立**：只差 1 行代码，结论就能翻转且指到行 —— 证明这份清单既不虚报绿灯、也不会永远红灯。
