## 0. 今日掌握点：改的是哪句裸报错？

**改前**（`public/mock.js`，从 Day 17 起一直这么写）：

```js
if (!res.ok) throw new Error('HTTP ' + res.status); // 400 / 404 / 500 一律当失败
```

问题有两个：
1. 用户会看到 **「HTTP 500」**——英文 + 状态码，看不懂也不知道该干嘛；
2. 更亏的是：服务端明明回了一句中文人话（比如「没有「美食」这个场景」），
   却因为**还没读响应体就先把请求判死了**，那句话被白白丢掉。

**改后**（同一个文件，三处调用统一走一个入口）：

```js
// 服务端的中文优先，拿不到才按状态码翻成人话
throw new Error(pickErrorMessage(res, body));
```

用户看到的话从「HTTP 500」变成「**服务暂时不可用，请稍后重试**」；
如果服务端有话，则原样展示服务端那句（例如「缺少必填字段：scene（场景）」）。

## 3. 三类错误提示统一 ✅

### 3.1 三大类是怎么分的（只看状态码，不看接口）

```
┌────────────────────────────────────────────────────────────────┐
│ ① 请求有问题  400 / 405 / 409 / 413  —— 你发来的东西不对，改一改再来 │
│ ② 找不到      404                   —— 你要的那条不在（可能被删了） │
│ ③ 服务异常    500                   —— 不是你的问题，稍后再试        │
└────────────────────────────────────────────────────────────────┘
```

分界线是「**重试有没有用**」：① 和 ② 重试一百次也一样（界面就不该给重试按钮），
③ 是"这次不走运"（给重试才有意义）。这条区分在契约第 1 节早就有，今天让代码真正长成这样。

### 3.2 服务端改了什么（`cloudfunctions/api/index.js`，VERSION → 1.5.0）

1. **`send()` 统一贴标签**：凡是 4xx/5xx 且 `ok:false` 的响应，出口处自动补一个
   `type` 字段（`请求有问题` / `找不到` / `服务异常`）。放在唯一的出口上统一，
   而不是每个报错手写——**一条错误都跑不掉**，格式也不可能不一致。
   新字段向后兼容：老前端不认识 `type` 也不受影响。
2. **③ 服务异常按"这次在做什么"换话**（`ERR500` 词典，原来只有一句"词库读取失败"，
   用在写入/删除上名不副实）：
   - 读（GET）→ 「词库读取失败，请稍后重试」
   - 写（POST/PATCH）→ 「词条写入失败，请稍后重试」
   - 删（DELETE）→ 「删除没有完成，请稍后重试」

### 3.3 前端改了什么（`public/mock.js` · `library.js` · `live.js`）

1. 新增 `humanizeHttp(status)`：状态码 → 三类人话（翻译表和服务端 `errKind` 一一对应）；
2. 新增 `pickErrorMessage(res, body)`：**服务端中文优先**，拿不到才退回按状态码翻译；
3. 新增 `apiFetch()` 作为所有真接口的统一入口——以前三处调用各自手写 fetch + 判错，
   现在错误翻译只写一份，以后新接口自动继承，**不可能再有人手写 "HTTP xxx"**；
4. `realLibraryRequest` / `apiGet` / `deleteNameRequest` 全部改走 `apiFetch`
   （删除那处顺带去掉了「删除失败（HTTP 500）」这种带状态码的半裸报错）；
5. 词库页 / 首页的错误状态把失败原因**说出口**：`showLibError(err)` / `showLiveError(err)`
   优先显示服务端给的人话，没有才用兜底句；页面上依旧只有人话，无堆栈无状态码。

### 3.4 改前 / 改后对照（今天那句话）

| | 写法 | 用户看到 |
| --- | --- | --- |
| 改前 | `throw new Error('HTTP ' + res.status)` | 「HTTP 500」（英文+状态码） |
| 改后 | `throw new Error(pickErrorMessage(res, body))` | 「服务暂时不可用，请稍后重试」（或服务端那句中文） |

## 4. 验证记录

### 4.1 本地起真实云函数打三类错误（故意不给密钥，让"服务异常"真的走到）

| 用例 | 方法 + 路径 | 状态码 | 响应（原样） |
| --- | --- | --- | --- |
| ① 缺必填字段 | `POST /api/names`（体 `{}`） | 400 | `{"type":"请求有问题","ok":false,"error":"缺少必填字段：scene（场景）"}` |
| ① 编号不对 | `PATCH /api/names/abc` | 400 | `{"type":"请求有问题","ok":false,"error":"地址里的编号不对：需要一个正整数，例如 /api/names/12（你给的是「abc」）"}` |
| ③ 删除时库连不上 | `DELETE /api/names/8?confirm=…` | 500 | `{"type":"服务异常","ok":false,"error":"删除没有完成，请稍后重试"}` |
| ② 地址不存在 | `GET /api/xyz` | 404 | `{"type":"找不到","ok":false,"error":"接口不存在"}` |
| ③ 读时库连不上 | `GET /api/scenes` | 500 | `{"type":"服务异常","ok":false,"error":"词库读取失败，请稍后重试"}` |
| ③ 写时库连不上 | `POST /api/names`（字段齐全） | 500 | `{"type":"服务异常","ok":false,"error":"词条写入失败，请稍后重试"}` |

三条 500 文案按动作各说各的，验证了 `ERR500` 词典真的在生效。

### 4.2 前端翻译函数（直接跑 `public/mock.js` 里的那份代码，不是复制品）

- `humanizeHttp`：400/405/413/422 → 「请求有问题，改一下再试」；404 → 「没找到这条内容，
  可能已经被删掉了」；409 → 「这条内容已经存在了」；500/503/504 → 「服务暂时不可用，请稍后重试」
- `pickErrorMessage`：服务端有中文 → 原样用（「没有「美食」这个场景」）；
  没回 body → 兜底人话
- 源码残留检查：**`'HTTP ' + res.status` 抛错已清零**（`public/` 下 0 处）
